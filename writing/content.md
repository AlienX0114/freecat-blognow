## 前言：本教程专为新手设计，贴合日常笔记、 项目文档 、Gi仓库协作场景，语法简洁易记，所有示例可直接复制到MD文件中练习，上手即会。

### 一、MD基础认知

1\. 什么是 Markdown ？：一种轻量级标记语言，用简单的符号标记文本格式，无需手动调整字体、对齐，写完直接渲染，兼容Obsidian、Git、CNB、 GitHub 等平台。

2\. 适用场景：日常笔记、项目文档、 代码注释 、Git仓库说明文档，语法统一，跨平台显示一致。

3\. 编辑工具：Obsidian、VS Code、记事本（需保存为.md后缀）、在线MD编辑器，所有语法通用。

4\. 核心原则：简单、高效，用最少的符号，实现最常用的文本格式，无需复杂操作。

### 二、核心基础语法（必记，新手优先掌握）

所有语法均附「示例+渲染效果」，复制示例到MD文件，即可查看渲染结果，建议边练边记。

#### 1. 标题（文档结构核心，常用）

用 `\#` 表示，# 数量越多，标题级别越低（1-6级），末尾加空格再写标题内容（适配所有平台）。

```csharp
# 一级标题（文档主标题，如你Git文档的“一、操作背景”）
## 二级标题（文档二级分类，最常用）
### 三级标题（二级标题下的细分）
#### 四级标题（较少用，按需使用）
##### 五级标题
###### 六级标题（最低级别，几乎不用）
```

渲染效果：与你Git文档中的标题完全一致，一级标题最大、最粗，逐级递减。

#### 2. 段落与换行（最基础）

无需额外标记，直接输入文字即可形成段落；换行需在末尾加 `两个空格` 或 `一个空行`（推荐空行，更整洁）。

```undefined
这是第一段内容，直接输入即可。（末尾加两个空格换行）
这是换行后的内容。

这是另一个段落（空一行分隔，更清晰），适合不同内容块的区分，如你Git文档中每个步骤的说明。
```

#### 3. 加粗、斜体、删除线（重点突出）

三种常用文本样式，适配笔记、文档重点标注，语法简单，可组合使用。

```cobol
**加粗**：用两个星号包裹（最常用，突出重点，如你Git文档中的报错信息）
*斜体*：用一个星号包裹（强调内容，如说明文字）
~~删除线~~：用两个波浪线包裹（标注废弃内容，如过时的命令）
**_加粗+斜体_**：组合使用（极少用，按需选择）
```

渲染效果：**加粗**、*斜体*、删除线、***加粗+斜体***

#### 4. 列表（分点说明，常用）

分无序列表（无顺序）和有序列表（有顺序），适配步骤说明、内容分类（如你Git文档中的操作步骤、冲突文件列表）。

##### （1）无序列表（最常用，用 - 或 \* 或 + ，推荐 - ）

```cobol
- 无序列表项1（如你Git文档中的冲突文件列表）
- 无序列表项2
- 无序列表项3（可嵌套）
- 嵌套列表项（前面加两个空格，再写 - ）
- 嵌套列表项
```

##### （2）有序列表（步骤类内容，用 数字+点+空格 ）

```markdown
1.  第一步操作（如你Git文档中的解决冲突步骤）
2.  第二步操作
3.  第三步操作
  1.  嵌套步骤（前面加两个空格，再写数字）
  2.  嵌套步骤
```

#### 5. 代码块（核心，适配你的项目代码）

用于插入代码（如Git命令、C语言代码），分「行内代码」和「代码块」。

##### （1）行内代码（嵌入文本中，如命令、文件名）

```typescript
用 ` （反引号，键盘左上角ESC下面的键）包裹，如：执行 `git pull` 命令拉取代码，打开 `USER/APP/robot_config.h` 文件。
```

渲染效果：用 \` 包裹的内容会变成代码样式，与普通文本区分开。

##### （2）代码块（单独成块，如Git命令、C代码，最常用）

````perl
用三个反引号 ``` 包裹，开头可加编程语言（如bash、c），实现语法高亮（适配Obsidian、Git、CNB），与你Git文档中的代码块完全一致。
```bash
# Git提交代码命令（bash语法高亮）
git add .
git commit -m "初始化项目"
git push
````

```cpp
// STM32简单代码示例（C语言语法高亮）

{
  while(1)
    {
       // 循环执行
    }
}
```

 ### 6\. 链接（跳转、关联文件，适配你的仓库）
用于插入网页链接、本地文件链接（如你仓库中的文档、图片），分「普通链接」和「Obsidian专属链接」。
 #### （1）普通链接（全平台兼容，Git/CNB/网页通用）
```markdown
![链接描述](链接地址)  // 图片链接（如你之前的图片插入需求）
[链接描述](链接地址)  // 文字链接（如网页、文档链接）
示例1（图片链接，适配Git/CNB）：
![STM32原理图](assets/STM32F407.png)
示例2（文字链接，如CNB仓库地址）：
[CNB远程仓库](https://cnb.cool/FYT2025-2026/Drone-26/holder_RM_26)
````

##### （2）Obsidian专属链接（仅Obsidian内使用，不失效）

```lua
// 链接Obsidian库内的文档或图片，随便移动文件夹不失效
[[文档名.md]]  // 链接库内MD文档
[[assets/图片名.png]]  // 链接库内图片
```

#### 7. 引用（标注引用内容，偶尔用）

用 `\&gt;` 开头，加空格，用于引用别人的话、报错信息、说明文字，适配文档注释。

```cobol
> 引用内容：如Git报错信息：error: remote origin already exists.
> 引用内容可以换行，每一行都加 > 即可
> 适合标注需要注意的提示、报错说明
```

渲染效果：引用内容会缩进，左侧有一条竖线，与普通文本区分开。

### 三、进阶常用语法（按需掌握，提升文档排版）

适合优化文档排版，让你的项目文档更整洁、专业。

#### 1. 表格（数据汇总，如你Git文档中的报错解决方案）

用于汇总数据、对比信息，语法简单，适配所有平台。

```ruby
| 表头1 | 表头2 | 表头3 | （表头，用 | 分隔，末尾可加 | ）
| :--- | :--- | :--- | （分隔线，:--- 表示左对齐，--- 居中， ---: 右对齐，推荐左对齐）
| 内容1 | 内容2 | 内容3 | （表格内容，用 | 分隔）
| 内容4 | 内容5 | 内容6 |
示例（适配你Git文档的报错汇总）：
| 报错信息 | 问题原因 | 解决方案 |
| :--- | :--- | :--- |
| error: remote origin already exists. | 重复绑定远程仓库 | git remote remove origin 后重新关联 |
| Automatic merge failed | 代码冲突 | VS Code解决冲突后提交 |
```

#### 2. 图片大小、居中（适配你的项目文档）

结合Obsidian+Git的需求，提供两种兼容写法，确保图片不失效、排版好看。

```cobol
# 写法1：Obsidian专属（改大小+居中，不失效）
![[assets/图片名.png|600#pic_center]]  // 宽度600，居中显示

# 写法2：全平台兼容（Git/CNB/Obsidian通用）
<img src="assets/图片名.png" width="600" align="center">  // 宽度600，居中显示
```

#### 3. 分割线（分隔内容块，整洁美观）

用三个及以上 `\-` 或 `\*` 或 `=` ，单独一行，用于分隔不同章节（如你Git文档中不同问题的分隔）。

```cobol
---  // 最常用，简洁
***  // 与---效果一致
===  // 线条更粗，较少用
示例：
## 一、操作背景
内容...

 ---  // 分隔线
 ## 二、完整操作日志
内容...
```

### 四、新手避坑指南（重点，适配你的使用场景）

- 1\. 语法符号后必须加 **空格**：标题（# 后）、列表（-/\*/数字后）、引用（> 后），否则无法正常渲染。

- 2\. 路径用正斜杠 `/`：插入本地文件（图片、文档）时，路径用 / ，不要用Windows反斜杠 \ （如 assets/图片.png ，不是 assets\图片.png），否则Git/CNB无法识别。

- 3\. 代码块必须闭合：三个反引号开头，必须三个反引号结尾，否则代码会错乱显示。

- 4\. 避免绝对路径：插入本地文件时，用相对路径（如 assets/图片.png），不要用绝对路径（如 C:\Users\用户\Desktop\图片.png），否则移动文件夹、换电脑会失效。

- 5\. 中文兼容：Obsidian、Git均支持中文文件名、中文内容，无需额外设置，直接输入即可。
